### Методика сканирования

Для анализа разработаны кастомные правила Semgrep,
учитывающие архитектуру и бизнес-логику микросервиса.

Правила направлены на выявление:

- нарушений аутентификации;
- состояний гонки;
- небезопасных конфигураций инфраструктуры;
- жёстко заданных учётных данных;
- ошибок работы с кешем;
- потенциально небезопасного формирования SQL-запросов.

[Кастомные правила Semgrep](rules/semgrep-rules.yml)

## Ручное добавление IDOR

**Идентификатор:** manual.bank.idor-bola.

**Классификация:** CWE-639, OWASP API1:2023 — Broken
Object Level Authorization.

**Связанная проблема:** CWE-306.

### Описание

Идентификация пользователя производится на основании
недоверенного HTTP-заголовка X-User-Id.

Проверки принадлежности банковских счетов и выборка
истории транзакций используют полученный идентификатор,
не подтверждая подлинность пользователя.

### Расположение

- [security.py:3–13](../microservice/app/security.py#L3-L13)
- [main.py:13–24](../microservice/app/main.py#L13-L24)
- [crud.py:5–16](../microservice/app/crud.py#L5-L16)
- [crud.py:43–66](../microservice/app/crud.py#L43-L66)

### Потенциальные последствия

- Нарушение конфиденциальности истории транзакций.
- Несанкционированные финансовые операции.
- Нарушение разграничения доступа между клиентами.
- Финансовые и репутационные потери банка.

### Рекомендации

- Использование доверенного механизма аутентификации.
- Проверка принадлежности объектов аутентифицированному
  пользователю.
- Тестирование межпользовательского доступа.

Уязвимость выявлена в результате ручного статического
анализа. Динамическая эксплуатация не проводилась.
Достижимость уязвимого кода зависит от устранения
существующих дефектов запуска API.

Ручная находка добавлена отдельной записью в копию
JSON-отчёта Semgrep. Оригинальный отчёт сохранён
без изменений.

### Проверка SQL Injection

В ходе сканирования выявлены два случая динамического
формирования SQL-запросов в app/crud.py.

Ручной анализ показал, что динамически формируются
номера параметров SQL-запроса, а пользовательские
данные передаются отдельно через параметры asyncpg.

Таким образом, наличие SQL Injection в исследуемой
версии исходного кода не подтверждено.

Информационные срабатывания сохранены в оригинальном
отчёте Semgrep.
