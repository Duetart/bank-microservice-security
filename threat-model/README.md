# 1. Модель угроз

Инструмент: OWASP Threat Dragon v2. Методология: STRIDE.

- [Оригинальный экспорт PDF](threat-dragon-report.pdf): DFD на странице 3, угрозы и контрмеры на странице 4, потоки на странице 5.
- [Редактируемая модель JSON](bank_threat_model.json): Local Session → Open an existing threat model.

## DFD

Пользователь обращается к FastAPI (`POST /transfer`, `GET /transactions`). PostgreSQL хранит счета и транзакции; Redis используется для чтения и удаления ключей (заполнение кеша не реализовано).

| Поток | Направление | Данные |
| --- | --- | --- |
| F1 | Пользователь → API | X-User-Id, from_account_id, to_account_id, amount_cents, limit, search |
| F2 | API → пользователь | status, transaction_id, история и ошибки |
| F3 | API → PostgreSQL | SELECT, UPDATE, INSERT |
| F4 | PostgreSQL → API | Владелец, баланс, tx_id, строки истории |
| F5 | API → Redis | GET / DEL ключей кеша |
| F6 | Redis → API | Значение/отсутствие ключа, результат DEL |

TB1 — внешняя граница; TB2 — логическая граница хранилищ. Публикация портов 5432/6379 создаёт условный риск обхода API при сетевой доступности. TLS в текущей конфигурации явно не настроен.

## Приоритетные угрозы

Оценка: вероятность × ущерб (каждый показатель от 1 до 5). Оценка экспертная, не CVSS. Все три угрозы открыты, меры предложены, но не внедрены.

| ID | STRIDE | Риск | Поверхность атаки и бизнес-ущерб |
| --- | --- | --- | --- |
| T01 | Spoofing / Information Disclosure | 5×5=25 | REST API, доверие к X-User-Id. Возможны чужие переводы и история, утечка банковской тайны, компенсации клиентам. |
| T02 | Tampering | 4×5=20 | POST /transfer, конкурентные операции; проверка баланса и списание разделены. Отрицательный баланс, финансовые потери и нарушение сверки. |
| T03 | Information Disclosure / Tampering | 4×5=20 | Опубликованный PostgreSQL и известные привилегированные реквизиты. При сетевой доступности — чтение или изменение данных, мошенничество и остановка операций. |

### Контрмеры

| Угроза | Тип / уровень | Мера и эффект |
| --- | --- | --- |
| T01 | Техническая / код | Проверять подпись JWT, issuer, audience, срок действия, получать subject из доверенного токена; проверять владение объектом. Снижает подмену личности и BOLA. |
| T01 | Архитектурная / инфраструктура | IdP, API gateway, TLS, запрет обхода gateway. Снижает риск недоверенного источника идентичности. |
| T01 | Процессная / SDLC | Review авторизации и негативные тесты доступа между двумя клиентами. Выявляет регрессии доступа. |
| T02 | Техническая / код | Атомарное условное списание либо блокировка строк с устойчивым порядком, проверка результата и идемпотентность. Снижает гонки и повторные списания. |
| T02 | Архитектурная / БД | Ограничения CHECK и FK, единая ACID-транзакция. Защищает финансовые инварианты. |
| T02 | Процессная / SDLC | Конкурентные тесты и сверка балансов. Обнаруживает нарушения целостности. |
| T03 | Техническая / инфраструктура | Ротация пароля, менеджер секретов, непривилегированная роль, TLS. Снижает вероятность доступа и масштаб ущерба. |
| T03 | Архитектурная / инфраструктура | Приватная сеть, закрытие опубликованного порта, ACL только для API. Снижает доступность БД атакующему. |
| T03 | Процессная / SDLC | Secret scanning, IaC review, тест сетевой доступности до релиза. Выявляет небезопасные конфигурации. |

SQL Injection не подтверждена: внешние значения передаются через параметры asyncpg, а динамически формируются только номера параметров.
