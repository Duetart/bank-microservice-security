# 1. Модель угроз

Инструмент: OWASP Threat Dragon v2. Методология: STRIDE.

- [Оригинальный экспорт PDF](threat-dragon-report.pdf): DFD на странице 3, угрозы и контрмеры на странице 4, потоки на странице 5.
- [Редактируемая модель JSON](bank_threat_model.json): Local Session → Open an existing threat model.

## 1.1. Data Flow Diagram (DFD)

Пользователь обращается к FastAPI (`POST /transfer`, `GET /transactions`). PostgreSQL хранит счета и транзакции; Redis используется для чтения и удаления ключей (заполнение кеша не реализовано).

| Поток | Направление | Данные |
| --- | --- | --- |
| F1 | Пользователь → API | X-User-Id, from_account_id, to_account_id, amount_cents, limit, search |
| F2 | API → пользователь | status, transaction_id, история и ошибки |
| F3 | API → PostgreSQL | SELECT, UPDATE, INSERT |
| F4 | PostgreSQL → API | Владелец, баланс, tx_id, строки истории |
| F5 | API → Redis | GET / DEL ключей кеша |
| F6 | Redis → API | Значение/отсутствие ключа, результат DEL |

TB1 — внешняя граница; TB2 — логическая граница хранилищ. Публикация портов 5432/6379 создаёт условный риск обхода API при сетевой доступности. TLS в текущей конфигурации явно не настроен.

## 1.2. Анализ наиболее критичных угроз

Для классификации угроз используется методология STRIDE.

Оценка риска рассчитывается по формуле R = L × I, где:

- L (Likelihood) — вероятность реализации угрозы, от 1 до 5.
- I (Impact) — потенциальный ущерб, от 1 до 5.

### Реестр угроз

| ID | Угроза | STRIDE | L | I | Риск |
|---|---|---|---:|---:|---:|
| T01 | Подмена личности и IDOR | Spoofing | 5 | 5 | 25 |
| T02 | Race Condition | Tampering | 4 | 5 | 20 |
| T03 | Компрометация PostgreSQL | Information Disclosure | 4 | 5 | 20 |

В OWASP Threat Dragon всем трём угрозам присвоен уровень High.
Числовая оценка используется для дополнительной приоритизации.

### T01. Подмена личности и IDOR

**Компонент:** Backend API.

**CWE:** CWE-306, CWE-639.

**Расположение в исходном коде:**

- [security.py:3–13](../microservice/app/security.py#L3-L13)
- [main.py:13–24](../microservice/app/main.py#L13-L24)
- [crud.py:5–16](../microservice/app/crud.py#L5-L16)
- [crud.py:43–66](../microservice/app/crud.py#L43-L66)

**Описание:** идентификатор пользователя определяется на основании
недоверенного HTTP-заголовка X-User-Id без полноценной аутентификации.
Проверки принадлежности счетов опираются на этот идентификатор.

**Поверхность атаки:** POST /transfer, GET /transactions.

**Потенциальный ущерб:**

- Несанкционированный доступ к истории транзакций.
- Выполнение финансовых операций от имени другого клиента.
- Нарушение банковской тайны.
- Финансовые и репутационные потери.

**Влияние на бизнес-процессы:** нарушение безопасности переводов,
обслуживания клиентов и конфиденциальности финансовых данных.

**Обоснование критичности:** угроза затрагивает обе основные функции
микросервиса и при работоспособном API не требует компрометации
инфраструктуры.

#### Контрмеры

| Тип | Контрмера | Уровень | Снижаемый риск |
|---|---|---|---|
| Техническая | Проверка подписи и атрибутов JWT | Код | Подмена личности |
| Техническая | Проверка принадлежности объектов аутентифицированному пользователю | Код | IDOR |
| Архитектурная | Централизованный IdP и API Gateway с TLS | Инфраструктура | Несанкционированный доступ |
| Архитектурная | Запрет прямого доступа к API в обход шлюза | Инфраструктура | Обход аутентификации |
| Процессная | Тестирование межпользовательского доступа и review авторизации | SDLC | Повторное появление IDOR |

### T02. Нарушение целостности баланса (Race Condition)

**Компоненты:** Backend API, PostgreSQL.

**CWE:** CWE-362.

**Расположение в исходном коде:**

- [crud.py:22–32](../microservice/app/crud.py#L22-L32)

**Описание:** проверка достаточности средств и последующее списание
выполняются отдельными SQL-операциями без необходимой блокировки
строки или атомарного условия проверки баланса.

При конкурентной обработке переводов несколько операций могут
использовать одно и то же исходное значение баланса.

**Поверхность атаки:** POST /transfer, конкурентные транзакции PostgreSQL.

**Потенциальный ущерб:**

- Возникновение отрицательного баланса.
- Списание средств сверх доступного остатка.
- Нарушение целостности финансовых данных.
- Финансовые убытки банка.

**Влияние на бизнес-процессы:** нарушение проведения платежей,
сверки остатков и финансового учёта.

**Обоснование критичности:** корректность денежных операций является
основным требованием к банковскому сервису. Наличие транзакции
PostgreSQL само по себе не предотвращает рассматриваемую гонку.

#### Контрмеры

| Тип | Контрмера | Уровень | Снижаемый риск |
|---|---|---|---|
| Техническая | SELECT FOR UPDATE либо атомарное условное списание | Код / БД | Конкурентное списание |
| Техническая | Проверка результата операции списания | Код | Нарушение целостности |
| Техническая | Использование ключей идемпотентности | Код | Повторное выполнение переводов |
| Архитектурная | Ограничения CHECK, FOREIGN KEY и единая ACID-транзакция | БД | Нарушение финансовых инвариантов |
| Процессная | Конкурентное тестирование денежных операций | SDLC | Регрессия бизнес-логики |

### T03. Компрометация PostgreSQL

**Компонент:** PostgreSQL.

**CWE:** CWE-798, CWE-284.

**Расположение в исходном коде:**

- [docker-compose.yml:7](../microservice/docker-compose.yml#L7)
- [docker-compose.yml:11](../microservice/docker-compose.yml#L11)
- [docker-compose.yml:23](../microservice/docker-compose.yml#L23)

**Описание:** конфигурация Docker Compose содержит жёстко заданные
привилегированные учётные данные PostgreSQL. Порт базы данных
опубликован на хосте.

При наличии сетевого доступа к опубликованному порту возникает
риск подключения к базе данных в обход Backend API.

**Поверхность атаки:** PostgreSQL TCP/5432, конфигурационные файлы,
учётные данные приложения.

**Потенциальный ущерб:**

- Массовая утечка банковских данных.
- Несанкционированное изменение балансов и транзакций.
- Удаление финансовой информации.
- Нарушение доступности микросервиса.

**Влияние на бизнес-процессы:** нарушение хранения финансовых данных,
проведения переводов и обслуживания клиентов.

**Обоснование критичности:** компрометация базы данных способна
затронуть всех клиентов одновременно и позволяет обходить механизмы
контроля на уровне приложения. Реализация угрозы зависит от сетевой
доступности PostgreSQL.

#### Контрмеры

| Тип | Контрмера | Уровень | Снижаемый риск |
|---|---|---|---|
| Техническая | Ротация паролей и использование менеджера секретов | Инфраструктура | Компрометация паролей |
| Техническая | Отдельная непривилегированная роль приложения | БД | Избыточные полномочия |
| Техническая | Шифрование соединений PostgreSQL | Инфраструктура | Перехват данных |
| Архитектурная | Исключение публикации порта БД, приватная сеть и ACL | Инфраструктура | Прямой доступ к PostgreSQL |
| Процессная | Secret Scanning и проверка инфраструктурных конфигураций | SDLC | Повторное появление небезопасной конфигурации |

### Вывод

Наибольшую опасность представляют нарушения идентификации
и авторизации пользователей, целостности денежных операций
и безопасности постоянного хранилища.

Выбранные угрозы затрагивают конфиденциальность, целостность
и доступность финансовых данных.

Все угрозы имеют статус Open. Контрмеры носят рекомендательный
характер. Исправление исходного кода не входит в рамки задания.

Результаты основаны на статическом анализе исходного кода
и конфигурации. Динамическая эксплуатация не проводилась.
